# 表单填写指南

## 当前网络已能直接访问国际互联网

选择“网络模式 → 默认直连，仅指定服务代理”。展开“服务规则预设”，只勾选需要使用代理出口 IP 的服务；例如勾选 Codex / OpenAI、Claude 和 Google / YouTube，取消开发者服务。Google / YouTube 包含 Gmail；登录和验证域名可能被多个服务共用。

其他网站无需填写，默认直连。需要额外代理的网站填入“始终代理”。公司内网启用“内网 DNS 分流”并填写域名后缀，DNS 留空使用系统 DNS，也可以填写实际公司 DNS 地址。内网和显式直连规则优先，出现覆盖提示时核对冲突。

生成结果以 `MATCH,DIRECT` 结束，不包含国内外 GeoSite / GeoIP 分流。`FORCE_PROXY` 只包含节点，不含 `DIRECT` 或 `AUTO`；导入客户端后手动选择出口，不会自动切换节点。普通域名和节点域名默认使用系统 DNS，需要代理的域名使用经过该代理出口的公共 DoH。

常规模式保留原来的国内直连、其他代理和公共 DNS 行为。规则只作用于交给 Mihomo 的流量；公司 DNS 和服务实际出口仍需在你的客户端中验证。

## 选择更多海外服务（v0.3.3）

展开“服务规则预设”，按 AI、社交、影音、办公、开发、游戏分类选择，也可以搜索服务名。新增 X / Twitter、TikTok 等服务默认关闭，按需勾选即可。分类批量操作只影响当前显示的服务，搜索不会清除已有勾选。

如果你当前网络可以直接上网，先选择“默认直连，仅指定服务代理”，再勾选需要使用自己 VPN 出口的服务。新增服务包含主页及常用登录、图片、视频域名，生成的代理规则与 DNS 同步。服务间共用的域名可能同时影响其他产品；这类影响和域名来源见[服务目录](SERVICE_CATALOG.md)。

已有的四项预设和之前保存的勾选保持不变。Google / YouTube 暂时保留组合项，包含 Gmail；开发者服务 / GitHub 也保留原有名称。服务清单不是对所有海外网站的穷尽，额外域名仍可填写“始终代理”。

## 先选哪一栏

| 你的需求 | 填写位置 | 生成行为 |
| --- | --- | --- |
| 公司 / 家庭域名必须由指定 DNS 解析 | 企业 / 家庭内网 DNS | 专用 DNS、排除 fake-IP、DIRECT 直连 |
| 普通网站不经过代理 | 自定义网站分流 → 始终直连 | DIRECT；不会自动排除 fake-IP |
| 普通网站必须经过代理 | 自定义网站分流 → 始终代理 | FORCE_PROXY |
| 没有额外需求 | 留空 | 使用服务预设、国内直连和代理兜底 |

内网已填的域名不必重复填“始终直连”。不要把整个 YAML 或 `DOMAIN-SUFFIX,...,DIRECT` 粘贴进表单。

## 企业 / 家庭内网 DNS

开启“启用内网 DNS 分流”。常规模式中两个输入框都要填写；默认直连模式中 DNS 可留空，使用系统 DNS。

**内网域名后缀**每行一个，例如：

```text
corp.example
admin.internal.example
home.arpa
```

填写裸域名，不加 `https://`、端口、路径、引号或 YAML 列表符号。后缀匹配包含该域名和所有子域：`corp.example` 会覆盖 `api.corp.example`。填完整主机名也会包含该主机名的子域，并非旧 YAML 的 `DOMAIN` 精确匹配。

**内网 DNS 服务器**填写你所在网络实际可用的 DNS IP，每行一个，例如：

```text
192.168.1.53
[fd00::53]:5353
```

这些只是格式示例，不保证适用于你的网络。支持 IPv4、IPv6 和可选端口，默认端口 53；所有域名共用这组服务器。不要把网关地址直接当作 DNS，需先确认它提供对应域名的解析；不要把公共 DNS 作为公司内部域名的备用解析器随意混入。

开启此配置不会连接 VPN，也不会修改操作系统、浏览器或正在运行的 Clash。导出配置并导入 Mihomo 后才生效。必须已能访问内网及 DNS 服务器。

`cluster.local` / `svc.cluster.local` 需要特别核实：DNS 可达不代表 Kubernetes 服务 IP 可达，浏览器的 `.local` 解析路径也可能不同。优先使用网络管理员提供的可从电脑访问的前端和 API 域名；只有确实需要旧集群域名且 DNS、网络都支持时才添加对应后缀。

## 自定义网站分流

两栏均每行一个域名、网址或 IP。例如：

```text
example.com
https://app.example.net/path
192.0.2.10
```

网址只取主机名，不能按 `/path` 分流。域名覆盖自身和子域；IP 只匹配该地址，不接受 CIDR 网段或逗号分隔规则。

- “始终直连”：适合不需要专用 DNS、但明确希望直接连接的网站。
- “始终代理”：适合现有预设外必须走代理的网站。
- OpenAI、Claude、GitHub、Google / YouTube 已有预设，通常无需重复填写。
- 内网和本地保护优先，其次自定义直连，再次自定义代理。重叠时阅读页面提示。

如果生成结果中同一个域名同时出现 `FORCE_PROXY` 和 `REJECT`，通常保留两行即可：前者选择代理，后者防止被跳过的请求落入后续直连规则。[查看逐行解释](RULES.md#为什么同一个域名有-force_proxy-和-reject-两行)。

## 自动保存与清空

v0.3.1 起，自定义直连 / 代理输入、内网开关、后缀和 DNS 输入自动保存到当前浏览器的 LocalStorage；包括尚未填写完成的内容。恢复后仍进行校验，非法输入不能导出完整配置。

- 同一浏览器、同一站点重新打开会恢复；不同浏览器、域名、协议或端口不共享。无痕模式通常在会话结束后清除。
- 清除网站数据会删除保存内容。保存内容未加密，同源脚本能访问，请使用可信托管站点和浏览器环境。
- “清空节点和结果”保留分流设置。
- “重置已保存设置”删除本工具保存项、清空自定义和内网字段，同时恢复服务预设与 CGNAT 默认值；保留节点、语言、主题和输出格式。
- v0.3.2 起网络模式、服务预设和 CGNAT 也会保存；旧设置自动补齐默认值。语言、主题及输出格式不持久保存。节点凭据、代理链接和 YAML 不写入本地存储。
- 读取 / 保存失败会在页面提示，此时不要认为下次一定能恢复；可检查站点存储权限或重置后重新填写。
